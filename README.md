# Quantum Code LP and Structural Obstruction Tools

This repository contains research software and persistent candidate weight distributions for the study of quantum stabilizer-code bounds, refined weight enumerators, and structural obstructions. It accompanies the corresponding manuscript; it is not a standalone proof of every bound or nonexistence statement discussed there.

The computational stages have distinct meanings. SLR linear programming (LP) enumerates ordinary weight-distribution candidates. Refined LP programs test additional necessary conditions on those fixed distributions. Structural verifiers apply exact counting or arithmetic arguments to selected candidate sets. A feasible LP candidate is not a code construction, a numerical LP infeasibility is not an exact certificate, and an inconclusive structural check does not establish existence.

## Relation to the manuscript

| Manuscript topic | Main program or data | Role |
|---|---|---|
| Shor–Laflamme–Rains (SLR) constraints; binary stabilizer codes | [`SLR3_LP.py`](slr_lp/binary/SLR3_LP.py) | Exact-integer three-case SLR feasibility and enumeration of ordinary binary stabilizer weight distributions; saves persistent candidate databases. |
| SLR constraints; nonbinary stabilizer codes | [`SLR_qudit.py`](slr_lp/qudit/SLR_qudit.py) | Exact-integer q-ary SLR feasibility and candidate enumeration, with an optional F_q-linearity restriction. |
| Binary refined weight enumerators | [`binary_RXxRY_stabilizer_reference_realLP.py`](refined_lp/binary/binary_RXxRY_stabilizer_reference_realLP.py) | Refined binary R_X × R_Y stabilizer-reference real-LP test of surviving SLR distributions. Numerical UNSAT is promoted only after the script's exact Z3 QF_LRA check. |
| H × RX refined LP | [`HxRX_qudit_stabilizer_reference_realLP.py`](refined_lp/qudit/HxRX_qudit_stabilizer_reference_realLP.py) | q-ary H × R_eta stabilizer-reference necessary-condition solver, including direct and candidate-database modes. |
| H × RX refined LP, q=3 MDS specialization | [`HxRX_MDS_q3_2x5_realLP_NO_TWISTS_farkas_no_z3.py`](refined_lp/qudit/HxRX_MDS_q3_2x5_realLP_NO_TWISTS_farkas_no_z3.py) | Specialized real-LP/Farkas workflow. It has no Z3 fallback; only a verified rational Farkas certificate gives an exact exclusion. |
| RX × RY refined LP; quantum MDS split distributions | [`RXxRY_MDS_primeq_stabilizer_reference_realLP.py`](refined_lp/qudit/RXxRY_MDS_primeq_stabilizer_reference_realLP.py) | Prime-q MDS joint-projection real-LP test with exact rational Farkas certification of numerical infeasibility. |
| Pauli shadow-coset packing | [`verify_n14_all47_packing_v2.py`](structural_obstructions/pauli_shadow/verify_n14_all47_packing_v2.py) | Exact shadow-coset counting screen for the supplied 47 SLR3 candidates for `[[14,3,5]]`. |
| Simplex representation and exact enumerator arithmetic | [`verify_n14_3_5.py`](structural_obstructions/simplex/verify_n14_3_5.py) | Exact-integer verification of the two embedded `[[14,3,5]]` candidate distributions (IDs 17 and 35) against the documented counting argument. |
| Binary shadow-coset counting | [`verify_n17_6_5.py`](structural_obstructions/verification/verify_n17_6_5.py) | Exact-integer verification of all 292 distributions in the supplied `[[17,6,5]]` candidate database. |
| Candidate distributions and refinement history | [`candidates/`](candidates/) | Persistent Python databases generated by the SLR solvers. Each stores `fixed_A`, candidate identifiers, solver status, and any recorded test details. |

The H × RX and RX × RY files are individual formulations or parameter-specific programs. Their presence does not mean that every candidate, parameter, or projection sweep in the manuscript has been completed. In particular, the repository records unfinished and unknown refined tests; consult each candidate database before interpreting a sweep.

## Requirements and installation

Python 3.10 or later is recommended. The exact minimum versions were not specified in the source files; package versions should therefore be regarded as unpinned.

```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# macOS or Linux:
source .venv/bin/activate
python -m pip install -r requirements.txt
```

The SLR solvers require SymPy and `z3-solver`. The refined real-LP programs require NumPy and SciPy; some exact certificate paths also use SymPy or Z3 as described in their source documentation. The three structural verification programs use only the Python standard library and exact integer arithmetic.

## Usage

From the repository root, inspect the stored SLR database for `[[14,3,5]]`:

```bash
python candidates/binary/candidates_n14_k3_d5.py --status
```

Re-run the exact shadow-coset screen over those 47 stored candidates:

```bash
python structural_obstructions/pauli_shadow/verify_n14_all47_packing_v2.py --require-47
```

Run the exact arithmetic check for the two embedded `[[14,3,5]]` distributions:

```bash
python structural_obstructions/simplex/verify_n14_3_5.py
```

Verify all 292 stored `[[17,6,5]]` distributions:

```bash
python structural_obstructions/verification/verify_n17_6_5.py
```

For a new binary SLR3 instance, use `python slr_lp/binary/SLR3_LP.py n k d`; for a q-ary instance, use `python slr_lp/qudit/SLR_qudit.py q n k d`. These are potentially long exact enumerations. The output databases are written under `candidates/binary/` or `candidates/qudit/`; an existing database is preserved rather than silently overwritten. For refined LP command-line options, run the selected program with `--help` and consult its source docstring. Pass the relevant candidate database explicitly when using candidate-list mode.

The scripts in `structural_obstructions/` accept optional `--report` paths for reproducible text reports. Their source help describes the available options.

## Nonexistence verification and current status

The manuscript develops nonexistence arguments for `[[14,3,5]]` and `[[17,6,5]]`. The checked artifacts and their scope are:

* For `[[14,3,5]]`, the exact shadow-coset program read 47 candidates: 15 were excluded by its counting test, 30 were not excluded by that test, and 2 were not applicable because the relevant dual weight-two condition failed. The separate exact simplex/enumerator script verifies the two embedded distributions labelled 17 and 35. The packing script explicitly does not prove SLR3-list completeness, and its “NOT EXCLUDED” result is inconclusive. These scripts should be read together with the manuscript's structural argument; neither alone is a complete certificate for every listed distribution.
* For `[[17,6,5]]`, the exact verifier checked all 292 candidates in the supplied database and excluded all 292 by its stated integer counting inequalities (258 in the `R3 > 17` class, 1 in `R1 > 1`, and 33 in the mixed class). It checks that the database marks the SLR3 enumeration complete; the computational result is conditional on that enumeration and the manuscript's stated structural bound.

Refined LP feasibility, SLR candidate enumeration, and structural exclusion are separate stages. A solver status of `SAT` means the tested necessary conditions did not exclude a candidate; it is not a code construction. A numerical HiGHS infeasibility is only a screen. It is reported as an exact exclusion only when that program verifies its required rational Farkas certificate or exact Z3 QF_LRA result. `UNKNOWN`, `RUNNING`, `ERROR`, `NOT TESTED`, and `NOT EXCLUDED` are not nonexistence results. No statement in this repository promotes numerical infeasibility alone to an exact nonexistence certificate.

See [`docs/computational-status.md`](docs/computational-status.md) for detailed scope, recorded unfinished states, and verification provenance.

## Reproducibility limitations

Solver versions and platform-specific performance are not pinned, and long SLR or refined-LP sweeps are not automatically repeated by the verification commands above. Stored databases preserve the results available when this repository was prepared, including incomplete or in-progress entries. Exact verification covers only the inputs and inequalities implemented by each verifier; separate mathematical lemmas and the completeness of an enumeration remain assumptions unless explicitly checked by that program.
